# 首轮评估与人工验收

## 1. 已确定的最小实验范围

首轮使用R03已接受的六条非距离事实，开发题从既有12题中取8题：D01、D02、D03、D04、D06、D08为正答题；D09与D12为边界题。共24分，分别报告正答18分与边界6分。选题、参考答案及证据位于 `evaluation/`，不得进入检索。

问题与scope是本次按用户开发授权采用的工作范围，不伪装成用户逐项给每个标准答案签字。实际执行前仍需确认配置及证据匹配；程序检查、证据预览、模型smoke和正式评分分别记录。尚未生成真实输出时不填成绩、不计算提升百分比。

## 2. 公平比较

RAG与无RAG使用同一生成模型、同一量化/runner、采样参数、输出上限、问题及共同范围指令。两组均不联网。主要差别是是否加入检索上下文；不能通过只给RAG更严格的“不编造”规则，或为无RAG提供较差参数来制造改善。

共同内容评分看事实正确性、参考版本与数量口径、是否作出无依据断言、可答问题的完整性。无RAG无需引用它没有得到的文档。边界遵从得分单独报告，不把模型遵守共同scope等同检索收益；也不奖励对所有问题一律拒答。

RAG另外报告：

- 检索是否覆盖问题必需的fact IDs（例如Recall@k）；命中来源不能只看字面相似。
- 回答中的引用是否属于实际检索结果，引用是否支持对应断言。
- 原文、提取事实、检索上下文和生成回答之间是否一致。
- 检索、生成和总耗时，首次加载与稳定请求分开；记录失败请求，不能只统计成功样例。

首轮题少、事实少，差值只能描述这些开发案例。最终报告应另留未参与调试的问题或证据单元；可报告每题配对结果和错误类别，不用小样本的偶然全对结果作泛化保证。

方法选择可从以下原始研究形成可核对的论证，而不是只引用工具教程：

- [Lewis等，2020，Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks](https://arxiv.org/abs/2005.11401)：说明参数知识与外部检索证据结合的研究背景。本原型是推理时检索，不能称为复现了论文中的端到端训练方案或其分数。
- [Liu等，2023，Lost in the Middle](https://arxiv.org/abs/2307.03172)：支持检查上下文位置与冗余影响。首轮保留少量可解释证据；后续可对证据排序和top-k做有界比较，不能先验宣称更长上下文更好。
- [Zhang等，2025，Qwen3 Embedding](https://arxiv.org/abs/2506.05176)：为小参数embedding选择及效率/效果取舍提供依据。论文基准不等于本地徒步语料的准确率，仍须检索回归和配对评估。

最终report应按实际使用的版本核对完整作者、出版信息并整理为APA 7；上述链接是研究入口，不是已经完成的正式参考文献表。

## 3. 需要安排的实验

| 顺序 | 问题 | 必须保存的证据 |
| --- | --- | --- |
| 数据边界检查 | 是否只取六条接受事实，停用距离是否被挡住 | manifest、接受hash、校验输出、故意违规输入的拒绝结果 |
| 程序离线检查 | 模型不可用时是否诚实显示状态 | 状态接口、证据预览与基线不可用的输出、业务测试 |
| 真实模型smoke | 本机模型与embedding路径能否实际完成请求 | 具体模型ID、配置、实际响应、耗时、失败信息 |
| 基线/RAG配对 | 在固定开发题上是否改善事实回答 | 两组原始回答、实际检索chunks、人工逐题分数及理由 |
| 有界消融 | 某一错误是否能由top-k或chunk策略修复 | 一项配置变化前后同题结果；失败和成本变化也保留 |
| 未见题检查 | 调整后是否还能处理未用于调试的案例 | 单独冻结的问题集、真实输出与人工评分 |

模型smoke可以证明一次接口/生成链运行成功，不能代替配对评估。离线词汇检索与Qwen embedding结果不得混为同一次语义检索实验；自动打分也不能未经核查替代人工判断。

## 4. 每轮人工验收

每轮只选择一个假设与一项有界变化，先准备可查看的代码、资料差异、输出及检查结果，再由用户接受或要求修改。原冻结审核版保持原样。用户的用途决定、事实接受、实现验收和公开部署是不同范围；接受路线标签不会恢复停用距离，也不会自动批准新来源。

本轮主要假设是：受控的资料选择和带来源的检索上下文能降低路线版本混淆及无依据回答。代码和文档只实现验证条件；是否实际改善必须由真实配对结果回答。

## 5. 必须展示的limitations证据

| 限制 | 如何展示，而不只写一句免责声明 |
| --- | --- |
| 资料少，覆盖偏窄 | 明确六个fact IDs、可答题与缺口；不把计划中的四套主线算作已覆盖 |
| 参考对象不同 | 展示Siwai与Nayapul、Deurali–ABC与MBC–ABC的边界例子及实际错误/正确回答 |
| 数据不能复现 | 将K09调查作为清洗历史：取得文件仍无法重现→按规则排除；不让旧值回到知识库 |
| 检索失败 | 保存问题、top-k实际命中、缺失的必要fact ID；区分没有数据与有数据未命中 |
| 生成失败 | 展示给对证据仍答错、无依据延伸或引用不支持的真实案例；没有失败时不捏造 |
| 模型与硬件限制 | 记录实际量化模型、runner、加载状态、内存/延迟观察；无模型时显式预览 |
| 安全价值尚未验证 | 不把行前信息问答准确率写成减少事故、医学适用性或当前路线安全的证明 |
| 评估偏差 | 区分开发题和未见题，单报边界分数，报告人工评分依据与小样本限制 |

## 6. 与作业和评分标准的对应

以下依据已读取的本地Assessment 2提取文本：`work/pdf_review/text.txt`（原PDF五页）、`work/main_review/assessment2.txt`和老师guide slides提取文本。Downloads中的原路径当前不可访问，因此不声称本轮重新打开了原附件；如老师更新LearnJCU版本，以其新文件为准。

已核要求包括：个人项目；使用现有开放权重LLM进行RAG和/或微调；组织适当数据；报告3000–4000词及代码/模型说明；15分钟口试；APA 7来源；AI使用声明；最终slides包含回应第9/10周反馈的反思。GitHub是作业推荐的版本管理方式。

HD rubric强调问题与数据的适切性、独立研究支持的技术选择、全面的效率/效果评估、准确技术语言、权威参考和批判反思。以下是项目证据安排，不是分数保证；漂亮页面、组件多或检查通过都不能单独满足这些要求。

| 老师要求展示的六项 | 本项目应交付的证据 |
| --- | --- |
| Problem statement | 目标人群、真实信息缺口、文档问答适用性及明确范围 |
| Document sample and source | 受控英文事实、原文定位、许可/署名、来源链与排除决定 |
| Chunking and embedding | chunk样例、为什么一事实一chunk、embedding与索引配置、后续有界实验 |
| Prompt design | 两组共同指令、检索证据的组织方式、无证据/范围外处理 |
| Evaluation examples | 检索内容、两组真实回答、人工评分、效率及错误分析 |
| Limitations and improvements | 上表可查看的失败/缺口证据及下一轮有理由的改进 |

报告结构沿作业建议：Introduction → Target problem → Choice of data sources → Methodology → Evaluation → Discussion → Conclusion → References。口试约15分钟，可分问题与范围2分钟、资料与许可2分钟、方法和页面演示4分钟、配对评估3分钟、限制与改进2分钟、反馈反思与结论2分钟。实际排练后调整，保留反思页并说明具体反馈如何改变项目。
